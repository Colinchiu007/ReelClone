# P2-1 微信支付分账 PRD

> 日期：2026-08-03
> 状态：Phase 0.3 需求定义

## 1. 背景

ReelClone 当前支付流程：用户购买套餐 → 全额进入平台商户账户 → 赠送积分。没有分账能力。

随着平台引入 UGC 模板创作者，需要将用户支付的金额按规则分给多方（平台 + 创作者/推广渠道），实现真正的创作者经济。

## 2. 业务目标

- 平台可配置分账接收方（创作者/推广渠道），每人有独立微信支付分账接收方账号
- 用户购买套餐时，按预设比例自动分账给各接收方
- 分账失败有补偿机制，不影响用户已获得的权益

## 3. 微信支付分账前置条件

微信支付分账需要商户号开通"电商收付通"能力，接收方需要是已入驻的子商户。本 PRD 假设：

- 平台商户号已开通分账能力
- 分账接收方通过管理员在后台配置（微信支付分账接收方的 open_id 或 merchant_id）
- 分账模式使用"及时分账"（支付完成后自动发起分账）

## 4. 核心功能

### 4.1 分账接收方管理

- 管理员可添加/编辑/删除分账接收方
- 每个接收方有：名称、类型（USER/CHANNEL）、分账比例（百分比）、微信分账接收方 ID、状态（ACTIVE/INACTIVE）
- 所有接收方分账比例之和不得超过 100%（平台自动分配剩余）

### 4.2 支付时自动分账

- 用户购买套餐支付成功后，回调处理中自动发起分账
- 分账金额 = 订单金额 × 各接收方比例（按分计算，微信要求分账金额为整数分）
- 平台获得剩余金额（总额 - 所有接收方分账金额）

### 4.3 分账回调处理

- 微信支付分账成功/失败回调通知
- 分账成功 → 记录分账状态
- 分账失败 → 记录失败原因，标记待重试

### 4.4 分账记录查询

- 管理员可查看所有分账记录（订单号、分账时间、各接收方分账金额、状态）
- 支持按订单号/状态筛选

### 4.5 分账重试

- 分账失败的记录可由管理员手动触发重试
- 重试次数上限 3 次

## 5. 不做的事（Scope Out）

- 不做自动对账（Phase 3 再做）
- 不做分账接收方的入驻审核流程（手动配置）
- 不做推广渠道分账（当前只做创作者分账）
- 不修改用户端体验（用户感知不变）

## 6. 验收标准

- [ ] 管理员可 CRUD 分账接收方，比例总和校验
- [ ] 支付成功回调后自动发起分账
- [ ] 分账回调正确更新状态
- [ ] 分账记录可查询
- [ ] 分账失败可重试（上限 3 次）
- [ ] Mock 模式下分账流程完整可测
- [ ] 所有新增代码有单元测试
