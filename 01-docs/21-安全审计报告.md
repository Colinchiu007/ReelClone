## 2. 认证与授权审计

### 2.1 JWT 校验链（已验证）

统一由 `libs/common/src/auth/access-token.strategy.ts` 承载，user-service 启用 `userStatusCheck: true`，共 6 项校验：

1. **Token 类型**：Access Token 与 Refresh Token 分离，类型不匹配拒绝
2. **jti 黑名单**：登出/改密后 token 立即失效（Redis 黑名单）
3. **密码修改踢下线**：`user:password-changed:{userId}` Redis 检查，改密后旧 token 全部失效
4. **tokenVersion**：版本比对，强制刷新机制
5. **Session Family**：继承关系校验，防 token 重放
6. **用户状态**：FROZEN / DELETED 用户拒绝访问

### 2.2 变更记录

- ✅ 8 个 deprecated `jwt.strategy.ts` 薄封装已删除（Task 24），全仓库仅一条 JWT 实现路径
- ✅ auth-service 异常统一为 `BusinessException`（Task 15），无 `UnauthorizedException` 泄漏细节
- ✅ 改密踢下线为 P0 安全修复（2026-07-29 完成），spec 断言覆盖 6 项校验

### 2.3 风险评估

**无新增可利用面**。JWT 密钥轮换流程与云托管密钥版本管理规范已文档化（见 `22-微信云托管运维手册.md` §11）。

| 防护项        | 实现位置                                                             | 验证方式                             |
| ------------- | -------------------------------------------------------------------- | ------------------------------------ |
| 回调签名验证  | order-service `OrderService.verifyCallbackSignature()`               | 25/25 单测 + E2E 004                 |
| 幂等处理      | `checkIdempotency()`（支付成功/失败防重复入账）                      | 单测覆盖双路径                       |

### 3.2 风险说明

- 测试文件 `wechat-pay-readiness.spec.ts` 含伪造测试私钥（`-----BEGIN PRIVATE KEY-----` 占位），**仅用于 readiness 校验测试，非真实凭证**，已通过静态扫描确认。
- `WECHAT_SUBSCRIBE_MOCK_MODE` / `WECHAT_PAY_MOCK_MODE` 为显式测试开关；production 下须保持 `false`（见运维手册 §5）。

## 4. SMS 安全审计（短信验证码）

### 4.1 已验证防护

| 防护项        | 实现位置                                                                     |
| ------------- | ---------------------------------------------------------------------------- |
| 密码学随机数  | `crypto.randomInt()` 生成 6 位验证码（替换 `Math.random()`）                 |
| 尝试上限      | 5 次尝试后锁定（`SMS_SEND_LOCKOUT_SECONDS`=60s）                             |
| 日志脱敏      | 验证码/手机号不在日志输出明文                                                |
| Mock 生产拒绝 | `SmsService` 构造时 `NODE_ENV=production` 拒绝 Mock 模式                     |
| 过期控制      | 验证码 300s 过期（`SMS_CODE_EXPIRE_SECONDS` 环境变量，默认 300，非法值回退） |

### 4.2 风险说明

**无新增风险**。已完成将 `SMS_SEND_LOCKOUT_SECONDS` / `SMS_CODE_EXPIRE_SECONDS` 从常量提升为环境变量（配合 `readPositiveInt` 防御校验，非法值回退默认 60s/300s，见 sms.service.ts），运营期可动态调节（见 §7 待办 T-4）。
